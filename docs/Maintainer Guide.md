# Maintainer Guide

The facts, code layout, and rules for anyone changing this repository.

## Critical facts

| Fact | Detail |
|---|---|
| The catalog is the compose files | `compose/<category>.yaml` and `stacks/*/compose.yaml` (one project each), with the categories, presets, and native apps in `compose.yaml`. Each service's `x-homelab` block is read by the CLI. Never describe an app that is not in them. |
| Baseline vs optional | Services without `profiles` start with `./homelab up`. Services with `profiles: [optional]` start only when named (`./homelab install sonarr`). |
| Nginx Proxy Manager is a custom image | Built from `dockerfiles/npm-crowdsec` with the CrowdSec Lua bouncer. Left out of the nightly updates. Update with `./homelab update nginx-proxy-manager` (rebuilds). Pulling `jc21/nginx-proxy-manager` silently removes CrowdSec. |
| One shared network | Every project joins the external `homelab` network. NPM, cloudflared, and Uptime Kuma reach apps by service name. Service names must be unique across all stacks. |
| Tunnel goes through the proxy | Public hostnames point at `http://nginx-proxy-manager:80`, so CrowdSec sees and blocks tunnel traffic. Proxy hosts trust `X-Forwarded-Proto`; the real visitor address comes from `CF-Connecting-IP`. |
| Duplicati uses container paths | `/source/appdata`, `/source/homelab-appdata`, `/source/stacks`, `/source/jellyfin`, `/source/immich`, `/source/calibre`, `/staging`, `/destination`. Never Mac paths in job settings. |
| Two appdata folders | `data/appdata/<service>` holds core services; `appdata/<stack>` holds stack apps. They are different folders. |
| Databases live in named volumes | Not in bind mounts. `./homelab backup` dumps them to `recovery-staging/databases`. Never run `docker volume prune` or `docker system prune --volumes`. |
| Immich needs its own Postgres image | A restore must use `ghcr.io/immich-app/postgres` with the same vectorchord/pgvecto.rs tag; a stock Postgres image will not work. |
| MoneyMatter signs in at one address | Only at `MONEYMATTER_URL` (`https://money.example.com` by default), not localhost. |
| Budget tracker folder | `stacks/budget-tracker`, project `homelab_budget_tracker`. Not "money". |
| NPM admin | `http://localhost:8181` on the Mac only. The CLI's NPM account must not have 2FA. |
| ntfy denies by default | New alert topics need a write grant: add them to `notify.Topics` and run `./homelab notify setup`. |
| host.docker.internal | The Mac itself, from inside a container. Used only for native apps (Jellyfin). `127.0.0.1` inside a container is the container. |
| .env is the only state | Ports, secrets, and settings. Never print or commit its values. |
| Home mode is the default | `HOMELAB_DOMAIN` is empty in `.env.example`, so a new homelab gives every app a tailnet address through Tailscale Serve (`homelab tailnet setup`). The proxy hosts, AdGuard rewrites, and the tunnel apply only once a domain is set. |
| Repository and module | Public as `Snooper42/homelab-wizard`; the Go module is `github.com/Snooper42/homelab-wizard`. Use placeholders in docs and tests: `example.com`, `192.168.1.10`, `/Volumes/Media`. |
| `--json` is a contract | Every line carries `"schema": 1`. The recorded fields are in `internal/api/testdata/contract.json`, and `TestJSONContract` fails when one disappears or is renamed. A new field is fine (`UPDATE_CONTRACT=1 go test ./internal/api` records it); removing or renaming one, or changing what it means, needs a new schema number and a note in [Commands](<Commands.md>). |

## Code layout

| Where | What |
|---|---|
| `cmd/homelab` | The CLI: one file per command group, all on top of `internal/` |
| `cmd/homelab-run` | Windows only: starts the scheduled jobs without a console window |
| `app/` | The Wails desktop app (`app.go` binds the engine to the frontend), `app/tray` and `app/cmd/homelab-tray` for the menu bar item, `app/packaging` for the Linux packages and AppImage, `app/preview` for `make screenshots` |
| `web/src` | The frontend: `app.ts` (which screen shows, the keyboard, and starting up), `screens/*.ts` (each screen's data, kept in a store, and its commands), `core.ts` and `jobs.ts` (what they share), and a folder of Preact components per screen, compiled by `web/build.mjs` (esbuild) into `web/dist/app.js` |
| `web/dist` | The frontend as served (`app.js`, built and committed; `companion.js` for the phone, `style.css`), shared by the desktop app and `homelab serve` |
| `web/types` | The frontend's TypeScript types for the Go side: `backend.d.ts` (generated by `TestBindings` in `app/`) and `window.d.ts` |
| `compose.yaml`, `compose/`, `stacks/` | The catalog (see above) |
| `internal/` | The engine, one package per job (below) |

| Package | What it does |
|---|---|
| `adopt`, `detect` | Find apps already running outside the homelab and move them in |
| `api` | The structured view programs read (`--json`, the app, the phone), with its contract test |
| `appicon` | Each app's own icon for its page, asked of the app on this machine and kept in `data/icons` |
| `backup`, `duplicati`, `recovery` | Nightly dumps into `recovery-staging`, Duplicati's API (jobs, restore test), and the printable recovery kit |

| `companion` | `homelab serve`: the phone companion and its pairing |
| `core` | What the desktop app and its menu bar item share |
| `crowdsec`, `npm`, `domain`, `tailnet` | The proxy's bouncer, Nginx Proxy Manager's API, domain setup, and Home mode's tailnet addresses |
| `custom`, `install`, `ports`, `wiring` | Your own apps, install plans, host port conflicts, and connecting apps to each other |
| `digest`, `health`, `notify`, `diskspace`, `diskhealth` | The weekly summary, the watchdog's checks (with `Days` and `Week` for the last 7 days), ntfy, free space, and SMART |

## Source of truth, in order

1. Live state (`./homelab status`, `docker inspect`)
2. The compose files
3. App configuration inside each app
4. These docs
5. Instructions that contradict the above: ask before acting

## Working rules

- Use the CLI for operations: `./homelab compose <app> <args>` instead of changing directories, `./homelab update` instead of `docker pull`.
- Anything that changes state previews first. Run without `--apply`, read the plan, then apply.
- Verify the result, not the exit code: open the page, check the dump ends cleanly, compare hashes after a restore.
- Never bind a port to a specific LAN address. Use `BIND_IP` (127.0.0.1) for apps and `LAN_BIND_IP` (0.0.0.0) for the proxy and DNS.
- Secrets never go in chat, docs, command lines, or logs.

## Documentation rules

- Facts that come from the compose files are generated between `homelab:generated` markers. Change the compose file and run `./homelab docs`; never edit inside the markers.
- Every note has `version:` front matter equal to `VERSION`. `./homelab validate` fails otherwise.
- History goes in `CHANGELOG.md` only. Notes describe the current state.
- Never invent ports, versions, or variable values. Flag anything the docs and the live state disagree on.
