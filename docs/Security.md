# Security

## Posture

| Area | Control |
|---|---|
| Inbound | No router ports. Public apps go through the Cloudflare Tunnel, which only connects outward |
| Edge | Cloudflare proxy with the free managed ruleset, Full (strict) TLS |
| Ingress | Every request, LAN or tunnel, passes Nginx Proxy Manager with the CrowdSec bouncer |
| Detection | CrowdSec reads the proxy's logs, bans attackers, pulls the community blocklist, and checks requests against virtual-patching rules (AppSec) |
| App ports | Bound to 127.0.0.1; only 53, 80, and 443 listen on the LAN |
| Containers | `no-new-privileges`, no raw Docker socket except Watchtower, read-only mounts where possible |
| Databases | Only reachable from their own stack's private network |
| Secrets | `.env` (0600, never committed) and Vaultwarden |
| Backups | Encrypted by Duplicati before they leave the Mac |
| Alerts | ntfy with deny-all access; only the alert topics are writable |

## Public apps

| App | Hostname | Authentication |
|---|---|---|
| Vaultwarden | passwords | Master password, 2FA required for every account |
| Immich | photos | Immich accounts |
| Paperless-ngx | docs | Paperless accounts, 2FA available |
| Navidrome | navidrome | Navidrome accounts |
| Feishin | music | Signs in to Navidrome |
| Audiobookshelf | audiobooks | Audiobookshelf accounts |
| Calibre-Web | books | Calibre-Web accounts (change the default admin first) |
| Komga | comics | Komga accounts |

Everything else is LAN-only: its hostname is not in public DNS and not in the tunnel. Making an app public is one line (`public: true`) and must meet the [Contributing](<Contributing.md>) checklist first. Admin apps are never public: `homelab validate` (and CI) refuses `public: true` on an infrastructure app (the proxy, AdGuard, Duplicati, Dozzle, and the like) or one marked `admin: true` (Uptime Kuma). Publishing one would first need Cloudflare Access in front of it, signing in at Cloudflare before the page loads.

## CrowdSec

| Part | Detail |
|---|---|
| Engine | `crowdsec` container, collections `crowdsecurity/nginx-proxy-manager` and `crowdsecurity/appsec-virtual-patching` |
| Log source | `npm-logs` volume, read-only, via `config/crowdsec/acquis.yaml` |
| Bouncer | Lua bouncer inside the proxy image, stream mode, refreshed every 10 seconds |
| Bouncer key | `CROWDSEC_BOUNCER_KEY`, registered by the engine at start |
| Whitelist | Private addresses are never banned (CrowdSec's default) |
| AppSec | The bouncer sends each request to CrowdSec's AppSec listener (`crowdsec:7422`, `config/crowdsec/appsec.yaml`) and blocks those matching a virtual-patching rule: exploits of known vulnerabilities in common apps. Generic rules are not loaded, to keep normal traffic untouched |
| Failure mode | If CrowdSec is down, the proxy keeps serving from its last list, and requests skip AppSec (fails open) |

Test it with the ban runbook in [Runbooks](<Runbooks.md>).

Bans only hold while the proxy's bouncer pulls them, so `./homelab doctor` says when it last did, and the watchdog alerts when it stops (missing, revoked, or no pull for 5 minutes). The app's Status screen shows **Protection**: bans enforced or not, and what CrowdSec caught this week.

## Accounts and secrets

- Every password is 40 random characters, generated by Vaultwarden, unique per app.
- Turn on 2FA wherever an app offers it (Vaultwarden, Paperless, the personal Nginx Proxy Manager admin). Setup's **Two-step sign-in** step walks through Vaultwarden and the proxy.
- The Proxy Manager automation account (`NPM_API_EMAIL`) cannot use 2FA because the CLI signs in with it. Keep a separate personal admin with 2FA.
- Close Vaultwarden sign-ups (`VAULTWARDEN_SIGNUPS_ALLOWED=false`) once accounts exist.
- Secrets never go into git, notes, chats, command arguments, or logs. The CLI reads them from `.env` and sends them only to the service they belong to.
- Keep an offline copy of the Vaultwarden master password and `DUPLICATI_SECRETS_PASSPHRASE` (the Homelab Secrets job's passphrase, from `.env`). Without them, nothing can be restored.

| Consumer | Access |
|---|---|

| Homarr (optional) | `docker-socket-proxy`, read-only: container list and engine info |
| Everything else | None |

## Updates

- Watchtower updates opted-in containers nightly; the proxy, databases, and MoneyMatter are updated by hand.
- `./homelab update nginx-proxy-manager` rebuilds the proxy on the newest `NPM_VERSION` you set.
- macOS and OrbStack: install updates by hand, then log in straight away.

## Review (October 2026)

Everything reachable from outside this machine, what guards it, and what is left. Reviewed against the code, not only the docs; re-run it before each release.

| Surface | Who can reach it | Controls | What is left |
|---|---|---|---|
| Public apps through the Cloudflare Tunnel | Anyone on the internet | Outbound-only tunnel; Cloudflare's managed rules; the proxy with CrowdSec bans and AppSec virtual patching; each app's own sign-in (2FA on Vaultwarden); `validate` refuses `public: true` on admin apps | A flaw in a public app before its patch: nightly updates and virtual patching narrow the window, they do not close it. Keep the public list short |
| ntfy (public, for phone alerts) | Anyone on the internet | Deny-all by default; publishing and reading need tokens (`NTFY_PUBLISH_TOKEN`, `NTFY_READ_TOKEN`, the phone's login); only published once the token exists | A leaked phone login reads the alerts (which name apps, never secrets): rotate it with `homelab notify setup` |
| The proxy and DNS on the LAN (80, 443, 53) | Every device on the home network | TLS with the wildcard certificate; app ports bound to `127.0.0.1` (`BIND_IP`); the same per-app sign-in | CrowdSec never bans private addresses, so a compromised device at home is not stopped by it; admin apps (the proxy, AdGuard, Duplicati) are reachable from the LAN behind their own passwords |
| Home mode: Tailscale Serve | Devices signed in to your tailnet | Tailnet only: Funnel is never turned on, so nothing is on the internet; WireGuard end to end | Every device in the tailnet reaches every app, admin apps included. Share the tailnet only with the household, or limit the `homelab` machine with Tailscale's access controls |
| Phone companion (`homelab serve`, 8099) | Home network and tailnet | Refuses public addresses and anything that came through Cloudflare (`Cf-Ray`/`Cf-Connecting-Ip`); never in the tunnel; one-time pairing codes (8 characters, 10 minutes, 10 wrong codes lock pairing for 10 minutes); device tokens stored as SHA-256 hashes and compared in constant time; read-only unless allowed; strict CSP and no framing | Anyone on the home Wi-Fi can try to pair, at the rate limit; a phone that is lost needs **Remove** in Settings › Phones |
| The desktop app | This machine only | Opens no port; secrets are copied to the clipboard (cleared after 90 seconds) and never sent to the page | Anything running as you on this Mac can read `.env`, as with any local secret store |
| Self-update (Nightly or `v*` release) | Whoever controls the GitHub repository | HTTPS from GitHub; the old app is kept until the new one is in place; build provenance attestations for tagged releases | Builds are unsigned until the Apple Developer ID is in place, so a compromised repository or GitHub account could ship a bad build. Signing and notarisation (1.0) close this; until then, keep 2FA on the GitHub account |
| Release workflow | Pushes to `main` and tags | `contents: read` by default; write only in the nightly and release jobs; no secrets in pull-request runs | The nightly job replaces the `nightly` release on every app change to `main`: review what merges |
| Diagnostics reports | Whoever you send one to | Passwords, tokens, emails, your account name, and the home folder are redacted (`homelab report`) | Read it before sending; app logs can still name hosts and IPs |

Findings that changed code in this review: none needed. Follow-ups: signed builds (1.0), and a second person's review of this table before 1.0.

## Incident response

1. Look: `cscli alerts list`, the proxy logs, the app's logs.
2. Contain: stop the app (`./homelab stop <app>`), or remove its public hostname by setting `public: false` and rerunning `./homelab domain setup` (the tunnel route stays until removed in Cloudflare; delete it there too).
3. Ban by hand if needed: `./homelab compose crowdsec exec crowdsec cscli decisions add --ip <address> --duration 24h`.
4. Rotate any secret that might have leaked (the app, `.env`, Vaultwarden).
5. Write it up in [Known Issues](<Known Issues.md>).
