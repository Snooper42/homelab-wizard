    Environment¶

    Every setting lives in ~/Homelab/.env, read by every Compose project. .env.example in the repository is the template.

    How .env is managed¶

    • ./homelab up (or install) creates .env from .env.example with mode 0600. It sets PUID, PGID, and TZ from this machine, and replaces every __REPLACE_ME__ with a generated secret.
    • Later runs add keys that are new in .env.example and never change values you already have.
    • Copy each generated secret into Vaultwarden as homelab - <service> <credential>.
    • .env is never committed (.gitignore), never printed by the CLI, and never pasted into notes or chats. ./homelab backup copies it into recovery-staging/secrets for the encrypted Homelab Secrets job.
    • Never add COMPOSE_PROJECT_NAME or COMPOSE_PROFILES: they would override each stack's own project name and the optional profile.

    This machine¶

    Variable Default Purpose
    TZ this machine's timezone Timezone for every container
    PUID, PGID your user and group (501, 20 on a Mac) File ownership for linuxserver.io images and Paperless
    BIND_IP 127.0.0.1 Where app ports listen. Keep it: other devices go through the proxy
    LAN_BIND_IP 0.0.0.0 Where the proxy (80/443) and DNS (53) listen; follows the machine's address
    ADGUARD_DNS_BIND_IP empty Where AdGuard Home's DNS (53) listens when not LAN_BIND_IP. On Linux, where systemd-resolved holds 127.0.0.53:53 (Ubuntu, Fedora), a new .env sets it to this machine's address, since a 0.0.0.0 bind would collide; homelab doctor warns when the address has changed
    DOCKER_SOCKET empty Docker's socket for the apps that talk to Docker (the socket proxy, Beszel's agent); empty is /var/run/docker.sock. With Docker run as you (SteamOS, homelab runtime install), a new .env sets your own, /run/user/<id>/docker.sock, and PUID/PGID to 0: a container's root is your account then, so what the apps write is yours
    DOCKER_API auto How the homelab reads the containers, their events, what they use, and the engine's info, and runs commands in them (the database copies, CrowdSec's): auto talks to the engine's API over its socket, or Docker Desktop's named pipe on Windows (found as the docker CLI finds it: DOCKER_HOST, the current context, OrbStack, Docker Desktop, a rootless engine, /var/run/docker.sock, \\.\pipe\docker_engine), and uses the docker command whenever that fails, resting the API 10 minutes; off uses the docker command only. Starting, stopping, and updating apps is docker compose either way. homelab doctor says which is in use, and the last fallback
    HOST_GATEWAY empty How containers reach this machine's own apps (Jellyfin, the phone companion, Ollama) as host.docker.internal; empty is Docker's host-gateway. With Docker run as you, a new .env sets this machine's address, since host-gateway is then Docker's own namespace, not this machine; homelab doctor warns when the address has changed
    KEEP_AWAKE true The awake job keeps this machine from sleeping while plugged in (the screen still sleeps). false: it sleeps as set. The menu bar item's (tray icon's) Keep this Mac/PC/computer awake while plugged in sets it, ticked while it is on; the awake job follows a change within a minute, and Setup says which it is
    BATTERY_SAVER true On a laptop running on battery, the watchdog pauses the heavy background apps (internal/battery lists them), and the awake job starts them again within a minute of being plugged in (the watchdog too, every 15 minutes). One that will not start stays paused for the next try without holding back the rest. Tdarr in the middle of a video finishes it first, taking no new one, and pauses within a minute of being done; its workers come back on power. false keeps them running
    PHONE_COMPANION true The serve job runs the phone companion on port 8099 (home network and tailnet only; phones pair with homelab phone pair). false: off
    HOMELAB_BASELINE empty small: up starts only updates, backups, and alerts, and you pick the rest (folders the desktop app makes). Empty or full: every app without a profile

    Domain, Tailscale, and Cloudflare¶

    Every new homelab starts in Home mode: HOMELAB_DOMAIN is empty, and a domain is optional.

    Variable Default Purpose
    HOMELAB_DOMAIN empty Empty: Home mode, every app at https://<TAILSCALE_HOST>:<port> (Tailscale). A domain such as example.com gives every app https://<subdomain>.<domain> through the proxy instead. An existing .env keeps its domain
    AUTO_DOMAIN true With a domain, each new app gets its proxy host (and tunnel hostname, if public) as soon as it is installed, once Set up the domain has run. false: only when you run Set up the domain
    TAILSCALE_AUTHKEY empty Optional secret. A reusable auth key signs Tailscale in without the browser; without one, homelab tailnet login opens Tailscale's sign-in page
    TAILSCALE_ROUTES this machine's network (192.168.1.0/24 in the template) The home network Tailscale makes reachable (approve the route in Tailscale's admin)
    TAILSCALE_EXTRA_ARGS empty Extra flags for tailscale up: --login-server=https://headscale.example.com signs in to a tailnet on your own Headscale server instead of Tailscale's. The nightly test uses it for a fake tailnet
    TAILSCALE_HOST empty Home mode only: this machine's tailnet name, written by homelab tailnet setup
    TAILNET_ADMIN_APPS true Home mode: false keeps the admin apps (the proxy, AdGuard Home, Duplicati, Dozzle) off the tailnet, so only this machine opens them; the household's apps stay on it
    POCKET_ID_API_KEY generated Pocket ID's static API key (STATIC_API_KEY), which homelab sso setup uses to make the apps' sign-in clients. A secret
    JELLYFIN_API_KEY empty A Jellyfin API key (Dashboard › API Keys). With it, homelab person makes each person's Jellyfin account, gives them a new password, and turns the account off when they are removed. A secret; Settings › Test checks it
    NAVIDROME_ADMIN_USER, NAVIDROME_ADMIN_PASSWORD empty A Navidrome administrator's login, best one of its own (homelab), for the same in Navidrome. Navidrome has no API keys. The homelab never changes this login's own password
    SSO_HOST empty Pocket ID's name (id.<domain>), written by homelab sso setup; the apps that sign in with it map it to this machine, so they reach it through the proxy
    VAULTWARDEN_URL, PAPERLESS_URL, KARAKEEP_URL, MONEYMATTER_URL, POCKET_ID_URL, NTFY_URL, NAVIDROME_URL, and the other *_URL settings empty The address an app is opened at, for the apps that need to know it (sign-in, links). Empty: https://<subdomain>.<domain>. Home mode writes the tailnet address, and Set up the domain clears it again (x-homelab url)
    CLOUDFLARE_API_TOKEN empty Secret. For the wildcard certificate and the tunnel's public hostnames. Permissions: Zone:Read, DNS:Edit, Cloudflare Tunnel:Edit
    TUNNEL_TOKEN empty Secret. The tunnel's token; cloudflared stays off until it is set
    COMPANION_PROXY_KEY empty Made by Set up the domain: the phone companion's proxy host sends it, so the companion knows a phone reached it over https and not over the Wi-Fi (Security, N25). A secret
    COMPANION_ACCESS_TEAM, COMPANION_ACCESS_AUD, COMPANION_ACCESS_CLIENT_ID, COMPANION_ACCESS_CLIENT_SECRET, COMPANION_AWAY_HOST empty The iPhone app away from home through the tunnel (ADR-0023), made by Setup's Reach Finances away from home (homelab phone away): the Cloudflare Access team and application, the household's service token (its secret given to a phone only when it pairs at home), and the companion's name through the tunnel. Empty: the companion answers only at home and on the tailnet

    Notifications and updates¶

    Variable Default Purpose
    NTFY_PORT 9293 ntfy on this machine
    NTFY_PUBLISH_TOKEN, NTFY_PUBLISH_AUTH empty Secrets, filled in by homelab notify setup: the publishers' access token, and the same as an ?auth= parameter for publishers that only take a URL
    NTFY_READ_TOKEN empty Secret, made by notify setup: read-only access for the app's list of recent alerts
    DESKTOP_ALERTS true Alerts also show on this machine's screen (Notification Center on a Mac). false: the phone only
    QUIET_HOURS 22-7 The night: alerts between these hours (22:00 to 07:00) reach the phone at ntfy's low priority, without a sound, unless serious (the vault unreachable, backups failing for two days). 13-15 for other hours; off sounds every alert
    HELPER_EMAIL empty Who helps you with the homelab: Email it to my helper writes to them with the diagnostics report
    HEARTBEAT_URL empty An external heartbeat (such as a healthchecks.io ping URL, period and grace 15 minutes). The watchdog pings it every run and pings /fail when something is down
    WATCHTOWER_SCHEDULE 0 0 4 * * * When the background agent runs the nightly updates (a cron with seconds): 4:00 AM daily, after the 03:30 backup. Named for Watchtower, which ran them before
    SOCKET_PROXY_VERSION v0.5.0 docker-socket-proxy's version, chosen by hand: it controls Docker for Homarr and Dozzle, so it never updates itself nightly (Security, M6)
    BESZEL_AGENT_VERSION 0.21.1 The Beszel agent's version, chosen by hand: it holds Docker's socket, so it never updates itself nightly (Security, N18)
    FRIGATE_VERSION, KOPIA_VERSION, NEXTCLOUD_VERSION 0.18.2, 0.23.1, 35 Kept until you choose a newer one: read the release notes, change the setting, then ./homelab update <app>. For Nextcloud this is the major version (the nightly updates bring its fixes); move it one major at a time
    UPDATE_CHANNEL testing What homelab upgrade and the app's update get: testing (every build of main, numbered v0.9.4-beta and on) or stable (only a new minor or major version, vX.Y.0). Before the first such version, stable has nothing to move to. Either way a git checkout moves only to a release whose build provenance checks out
    UPDATES_PAUSED not in the template Written by homelab updates pause (removed by resume): the agent runs no nightly update until it is resumed
    UPDATE_COPY_LIMIT 2GB The largest folder or volume homelab update copies before an app's update, for its rollback (500MB, 10GB; 0 copies any size). A larger one is left out and named in the update's output; databases are dumped whatever their size
    AUTO_ROLLBACK true The watchdog rolls back an app that stays unhealthy, keeps restarting, or does not answer 20 minutes to 6 hours after its update, and holds its updates; with its data from before the update only if it was never well after it. false: it only alerts
    AUTO_HEAL true The watchdog restarts an app that is unhealthy or not answering on two checks in a row, and makes one whose container is gone again (once in 6 hours at most); it stops an app Docker restarted 3 times in an hour, with its last log lines in the alert. false: it only alerts
    OLLAMA_MODEL empty The Ollama model that explains logs (Explain this under an app's log, homelab logs <app> --explain), such as llama3.2. Empty: the first of Llama, Qwen, Gemma, Mistral, or Phi that Ollama has. Ollama's own OLLAMA_HOST says where it runs (this machine by default)
    <APP>_DIGEST (PAPERLESS_DIGEST, VAULTWARDEN_DIGEST, …) not in the template The version each app the nightly update moves forward runs: its image and that image's digest (ghcr.io/paperless-ngx/paperless-ngx:latest@sha256:…). Written by homelab update, a rollback, and the watchdog when what runs changes; homelab up, install, a move, and a rebuild start that version again, so a restore or a new machine opens the data with the version that wrote it. A version you choose by hand (IMMICH_VERSION) wins: a kept line for another image is left alone until the app runs the new one. Delete a line to let that app start on its newest version
    UPDATES_HELD empty Apps left out of nightly updates (after a rollback, or homelab updates hold). Written by the CLI; homelab updates release <app> takes one off

    Tidy Up¶

    Tidy Up sorts, tags, and shrinks the libraries on the media drive (MEDIA_ROOT). Settings (its Tidy Up section) changes them.

    Variable Default Purpose
    TIDY_UP true false turns its background work off (the inbox, Tdarr's finished work, and the nightly sweep); the screen still works
    TIDY_INBOX, TIDY_INBOX_FOLDERS true, empty File what finishes downloading in Downloads and DOWNLOADS_ROOT into the libraries; other folders to watch instead, separated by ;
    TIDY_INBOX_WHEN arrive When the inbox files: arrive (checked every minute), daily (once a day, after 03:00), or manual (only on Tidy up now)
    TIDY_SCRUB true Every night at 03:00, leftovers whose film, song, or book is gone (posters, .nfo and subtitle files, empty folders) go to the Trash
    TIDY_TDARR_REST, TIDY_ARR_REST true Tdarr, and the download apps (Sonarr, Radarr, Lidarr, Prowlarr, Bazarr, FlareSolverr, qBittorrent, Gluetun), rest stopped while they have nothing to do, freeing their memory; false keeps them running
    TIDY_KEEP_LANGUAGES eng The audio and subtitle languages films and episodes keep (ISO 639-2: eng, jpn); Tdarr removes the rest when it shrinks them
    TIDY_VIDEO_CODEC hevc What Tdarr shrinks video to: hevc (plays everywhere) or av1 (smaller, newer players)
    TIDY_SHRINK_LOSSLESS true New lossless music (FLAC, WAV) is stored as 256k AAC, about a fifth of the size; false keeps it lossless
    TIDY_LYRICS embed Lyrics inside each song file (embed) or in a .lrc file beside it (lrc)
    TIDY_MUSIC_ENGINE empty Where beets runs: local (this computer, fastest) or container; empty picks local when Python can make its own environment here
    PLEX_URL, PLEX_TOKEN, PLEX_PATH_MAP empty A Plex server to tell about each new or changed file, its token, and how its folders map to this computer's (/Volumes/Media=/data)
    AUDIOBOOKSHELF_API_KEY empty Audiobookshelf's API token (Settings › Users › your user), so Tidy Up tells it about new files
    TDARR_API_KEY generated Tidy Up's key to Tdarr, which Tdarr takes as its own when it starts. A secret
    TDARR_USER, TDARR_PASSWORD empty An older Tdarr's sign-in: made by Tidy Up (user homelab) when Tdarr had none; one you made first goes here

    App ports¶

    Each app's port on this machine is a variable named <APP>_PORT (for example VAULTWARDEN_PORT=8087). The installer moves a port if something else already holds it and writes the new value back. Inventory shows the current addresses.

    Adding a variable¶

    1. Add it to .env.example (secrets as __REPLACE_ME__, with a comment saying what it is for).
    2. Add it to this page.
    3. ./homelab up adds it to .env. ./homelab validate fails if a requires entry, or a port variable without a default, is missing from .env.example.
