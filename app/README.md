# Homelab Wizard (desktop app)

A [Wails v2](https://wails.io) app over the same engine as the `homelab` CLI: Go in `app.go`, a plain HTML/JS frontend in `../web/dist` (no npm build step; the root module embeds it as package `web`, so `homelab serve` shows the same screens on a phone). What the app shares with the CLI and the menu bar item is `internal/core`.

| Screen | What it does |
|---|---|
| Choose stacks | **Start here** cards for the five starter picks, then **Add more** with every app by category and the presets (the bundles only). A search box (by name, what an app does, or what it replaces: "Spotify" finds Navidrome). Every app with what it replaces, whether it is running, and Open and Settings links. Tick apps or click a preset; dependencies are added and the plan updates live. The plan says in one line how many apps it installs and lists the ones you picked; helpers, apps already running, port moves, and settings written wait under **Details**. An app that needs a setting (the VPN key for qBittorrent) names it, and the field appears below with where to find it; values go to `.env` and are never shown back. Install streams each step. |
| Backups | Each installed app's newest database dump or volume archive, one line each (when, its size, and how many are kept), grouped as Stale (over 26 hours), Up to date, Paused (its app waits for a drive that is unplugged; folded, with the drive named), and Not copied yet; when the settings file was last copied, where the backups go (Off-site: Proton Drive, the Backup drive), and the last restore test with how long it took (or a failure since, in red; hover for the drills on record), with **Test a restore** in its tile. *Encrypted to …* lists each Duplicati job, its size, and when it runs next (hover for its last run), and its error (it signs in to Duplicati's API with `DUPLICATI_PASSWORD`; while Duplicati waits for its drive, it says so). With no jobs yet, it offers **Create the backup jobs** (`homelab duplicati setup`). **Back up now** runs the nightly backup on the spot; **Test a restore** (once the Homelab AppData job has run) has Duplicati restore a dozen files and checks each against the live one; **Open Duplicati** opens Duplicati; **Recovery kit** opens the printable page. The vault export, **Moving to a new machine**, and how the backups work are one line each that opens for the rest. Moving has **Move out…** (asks where to save the file, then backs up, stops the apps, and packs them; click twice) and **Move in…** (choose that file on the new machine), the same as `homelab move out` and `move in`. |
| Status | Tiles for running apps, what needs a look, the yearly savings (with a sparkline of the last 90 days and the change, from the nightly backup), and nightly updates. Apps by category, changing as things happen (the engine's events; checked again every minute), with only what changed redrawn, so the keyboard keeps its place: a category where every app runs folds into one line with its apps' names (click to open it; **Show every app** opens them all, and the choice is kept), while what needs a look and a category with something stopped stay open. Each row shows the app's state, one address (its address on this machine in the tooltip), how long it has been up, a *restarted N×* badge when Docker had to restart one that stopped on its own, *Not answering* (with why) when it runs but its page does not answer, *settings changed* when it still runs settings that changed since it started, and *x% up this week* when it passed fewer than 99% of the watchdog's checks in the last 7 days. Each row has one button, Open (or Start when stopped), and the chevron to the app's page; a click anywhere else on the row opens the page too. The rest is on the page (below). Baseline apps that are missing get Install. **Fix it** (`homelab fix`) appears when a baseline app is down, one is unwell or not answering, or one runs changed settings, and shows the plan first. **Watchdog** shows its last run (every 15 minutes once the jobs are installed): all checks passed, or each failing check with what it said and since when and a **Fix it** button, and a note when it has not run for 45 minutes. **Protection** (while CrowdSec and the proxy run) says whether bans are enforced, with **Fix** when they are not (it reconnects the proxy to CrowdSec), how many attacks CrowdSec caught this week and how many addresses are banned now, and the latest three with their address, country, and network, read once a minute. **Recent alerts** lists what Watchtower, Duplicati, Uptime Kuma, and the watchdog sent to ntfy in the last 12 hours, with a green dot for recoveries and red for urgent ones (it needs the read token `notify setup` makes). **What's using power** shows each busy app's share of a core with a line of its last five minutes, sampled every 10 seconds while Status is open. **Photos per person** and **What the apps keep** (the six largest folders in `data/appdata`) come from the nightly backup's `data/storage.json`. **This week** is the Sunday summary (`homelab digest`) at any time, with what needs a look marked. |
| Updates | One line at the top of every screen, from one look for the homelab files and the app's own build together (`LookForUpdates`, every 15 minutes by the wall clock and when the window comes forward after 10; the new build downloads ahead): *Homelab Wizard 0.15.0 is ready* with **What's new**, **Later**, and **Update now** (`UpdateNow`: `homelab upgrade`, then the new app in place, which opens again), then *Updating…* with a bar, and *Updated to 0.15.0*. When it cannot finish by itself it says why in one sentence (changes of the folder's own, a copy that cannot replace itself, with **Download it**). **Later** hides it until something newer; the sidebar's **● Update ready** brings it back. Settings › This Mac › Updates: when it last looked, **Look now**, and *Install updates when I quit the app* (on until turned off; not where installing asks for a password). The menu bar item's *Update to 0.15.0* opens the window and updates. |
| Setup | While anything needs you (and only then: it leaves the sidebar once every step is done, and comes back with a count when one comes undone): four tiles on how this machine looks after the homelab (the background agent, with **Start it** when it is stopped; the runtime; the power; the room on its disk), then **Finish setting up**, the steps grouped as Needs you, Can wait, and Done, one line each until opened with a live check per step (the tailnet addresses in Home mode, or AdGuard answering, token valid, certificate served, and tunnel running with a domain; jobs installed), each saying what it gives you before how, a button for each step the CLI can do, and a Done box for the ones only a person can (a router reservation). **Do the steps I can** runs every ready step in turn and stops at the first that fails or needs you. Same checklist as `homelab setup`. **Settings › This Mac** holds the machine's details (the machine, the runtime, what runs in the background, the menu bar item, the homelab folder, the disks, the version) and **Make a diagnostics report**, which ends with **Show in Finder**, so the file is one click from being shared; Status keeps the four tiles as one line. Beside the version it says whether GitHub has new changes; when it does, a card on Setup lists them with **Release notes** and **Update** (`homelab upgrade`: fast-forward only, then `up`). On a Mac, **Update** then downloads the newest app build (the latest build (Releases › Latest), or the newest `v*` release with `UPDATE_CHANNEL=stable`), checks its SHA-256 against GitHub's, replaces the running app, and opens it again (`internal/selfupdate`); when only the app is behind, the card offers **Update now**. On Windows and Linux the card opens the release builds instead. The sidebar says **● Update ready** on every screen when either has an update (checked at start and every hour). Release builds carry their commit (`-X main.commit`) for this comparison. The machine card shows the free space on each disk the homelab writes to (in red under 5%, with where to free some), starts the tray at login, and the AppImage adds itself to the app menu (with its icon) on request; when it starts from a new place and the file those entries start is gone, it points them at itself. |
| An app's page | The chevron at the end of a row, or a click on the row (on a phone too). The app's own icon (asked of the app on this machine once a week; its first letter when it has none), its name and state ("Running · up 8 hours") with Restart and Stop as one group (Start when stopped), Open on a phone, and Open; four tiles: its address (Copy, and whether it is reached at home and on the tailnet or also through the Cloudflare Tunnel), what it uses now (memory and processor from `docker stats` every 10 seconds, and its size on disk from the nightly backup's `data/storage.json` when listed), this week (seven bars from the watchdog's runs per day, orange or red on a day with missed checks), and the last backup (with the last restore test and a link to Backups). Then its log (the last 200 lines, Show more of it for 2000, warnings and errors tinted, Dozzle while it runs, **Explain this** when Ollama has a model, the answer in a card with Ask again and Hide), Updates (when it was last updated, with Roll back, and Check for an update), Who uses it (the household members whose apps include it, for apps people sign in to, with Sign-in details where the homelab made a login), Settings (**Nightly updates** and **Tell me if it stops** as switches that change at once and go back with the reason if the change fails; what the nightly backup keeps of it, with no switch), and More (Back up now, which runs on Backups, Open Backups, and **Remove**: a backup of it first, then its container goes and its data stays; not on a phone). It belongs to Status: Status stays picked in the sidebar and ‹ Status goes back. |
| Status: moving and cleaning up | Apps running *elsewhere* (an older setup) get **Move in**, which shows `homelab adopt`'s plan and runs it on confirm. **Clean up old containers** does the same for `homelab cleanup`. |
| Add your own app | At the bottom of Choose stacks: a name, an image, a web port, and folders to keep. Runs `homelab custom add`, then ticks the new app so the plan shows what installing it does. |
| Settings | The page list in groups: this machine (**This Mac**, with the machine's details and **Make a diagnostics report**; Storage; Appearance), the household (People, Phones), and reaching the apps (Domain, Notifications); then the installed apps folded by their category on Status, and the apps not installed folded as one (a search opens the folds with matches). A setting shows its name in words, its `.env` name on hover and while searching, a switch beside its name, and help without the commands behind it or a switch's true and false. **People**: the household (`homelab person`), each with **Welcome page**, **New sign-in link**, and **Remove** (sign-in off, data kept), and **Add a person** with their name, email, and the apps they use; without Pocket ID running it offers **Install Pocket ID**. Then **Phones**: the phones paired with the phone companion (`homelab serve`), with when each was last seen, Allow changes or Make read-only, Remove, and Pair a phone (a QR code drawn on the Go side, the one-time code, and the links, plus the same link with `&kiosk` for a TV or a wall tablet, which then shows Status alone, large, without buttons). Then `.env` as a form, grouped and explained from `.env.example`: the everyday settings first (where things are, the accounts, how it behaves, and what an installed app or a Setup step needs), with ports, versions, generated passwords, and internal addresses behind **Show all settings**; search looks through everything. Passwords and tokens are never sent to the page: their fields say whether a value is set, and empty keeps it. After saving, each setting shows whether its setup step now passes. Logins, tokens, the heartbeat URL, and the backup and media folders have a **Test** button that saves a value you just typed, then checks it with the real service (AdGuard and NPM sign-ins, the Cloudflare token reading the zone and the tunnel, the tunnel token, a heartbeat ping, writing a file in the backup folder). **Copy** beside a saved password or token puts it on the clipboard (from the Go side, so it never reaches the page) for the password manager, and clears the clipboard after 90 seconds. Folder settings (`BACKUP_DESTINATION`, `MEDIA_ROOT`, and the like) have **Choose…**, the system folder picker. |
| Connect the apps | After an install (or with Status › More… › Connect apps): Prowlarr gets Sonarr, Radarr, and Lidarr and FlareSolverr; qBittorrent becomes their download client (needs `QBITTORRENT_PASSWORD` in `.env`). Seerr and Bazarr need a sign-in, so they show as next steps. Same engine as `homelab wire`. |
| Menu bar | Laid out as the approved mockup, the same on every system in its own menus. First, at a glance: a coloured dot and how many apps run ("33 of 34 apps running"), then how many need a look and when the homelab was last read ("One needs a look · checked just now"). Every line up to the first separator has a mark, so the words line up: the first line (how many apps run) its state dot, and a click opens Status; the grey line under it none. Then only what needs a look: an orange dot for each app restarting, unwell, not answering, or not running, by name (up to three lines, the last saying how many more), for the checks the watchdog alerted about ("3 watchdog checks failing", the names in its tooltip), and for the newest alert from the last 12 hours (each click for Status); a tick for when the last backup ran ("Backed up at 3:12 this morning"; an orange dot and a warning past 26 hours; click for Backups); an arrow when updates are ready ("2 updates ready", or a newer app build; checked once an hour; click for Setup). The marks are drawn at two pixels a point, with smoothed edges, as .ico on Windows. Then Open Homelab Wizard; Open an app, with the installed apps under their categories, each with a dot for its state (green running, orange needs a look, grey stopped) and ending with Every app (Status); Back up now; Update apps now; pause or resume nightly updates; Keep this Mac (PC, computer) awake while plugged in (a check box, ticked while `KEEP_AWAKE` is on; a click turns it off or on, and the awake job follows within a minute); and Quit Homelab Wizard…, which opens the app to ask before it stops the homelab. The tooltip adds what the running apps replace in subscriptions a year. Starts with the app and refreshes every minute and on each change the engine reports. |

Setup's machine card turns on **Start at login** for the menu bar item (the tray icon on Windows and Linux): a LaunchAgent in `~/Library/LaunchAgents` on macOS, an entry in `~/.config/autostart` on Linux (for an AppImage, it starts the AppImage file), and a value in the user's Run key on Windows. Keyboard: Cmd (Ctrl on Windows and Linux) with 1 to 5 picks a screen in sidebar order, comma opens Settings, R refreshes the screen (F5 too, on Windows and Linux), F finds (Choose stacks, Settings), plus and minus make the text bigger or smaller (80% to 200%, kept on this machine) with 0 back to the usual size, and Escape clears a search. Every link that acts (Open Setup, Show, go back) is reached with Tab and pressed with Enter or Space. For VoiceOver, picking a screen moves to its heading and marks the sidebar button as the current page, logs are announced as logs, and errors and results are read out when they appear. On the Mac the window follows the platform: the window buttons sit in a translucent sidebar (as in Finder and Mail), and the menu bar has the app, Edit, View (the screens, Settings… ⌘, and Reload ⌘R), Window, and Help menus, with an About panel showing the version. On Windows 11 the navigation pane sits on Mica (build 22621 and later; older Windows keeps an opaque window) with Segoe UI Variable, a grey selection and the accent pill beside it as in Settings, accent badges, 4px controls, and thin scroll bars; on Linux the sidebar and controls follow GNOME's Adwaita, and on KDE Plasma (SteamOS's desktop mode) Breeze: its greys, Noto Sans, bordered buttons, and the accent-tinted selection. Each platform uses its own greys and accent colour rather than the logo's navy. Everywhere, buttons show the arrow rather than a hand, labels do not select (fields, logs, and errors do), and focus rings appear for the keyboard only. The menu bar item runs as its own process. On macOS it is a helper inside the bundle (`Contents/Helpers/homelab-tray`, built from `cmd/homelab-tray`), because Wails and the tray library cannot share one binary there; on Windows and Linux the app binary runs it with `--tray`. On Linux it needs a desktop with a status-notifier tray (KDE, or GNOME with the AppIndicator extension).

## Run and build

Needs Go 1.26+ (Go fetches the version in `go.mod` by itself) and the Wails CLI: `go install github.com/wailsapp/wails/v2/cmd/wails@v2.16.0`, then `wails doctor` for the platform prerequisites (Xcode command line tools on macOS; `libgtk-3-dev` and `libwebkit2gtk-4.1-dev` on Linux, built with `-tags webkit2_41`; WebView2 on Windows, already present on Windows 11).

```bash
cd app
wails dev                 # live window; edits to ../web/dist reload (wails.json assetdir)
wails build               # build/bin/Homelab Wizard.app (macOS), homelab-wizard(.exe)
```

The packages are built by `.github/workflows/release.yml` ([Releasing](../docs/Releasing.md#each-platforms-build) lists what each holds):

| Platform | How | Files |
|---|---|---|
| macOS | `wails build -platform darwin/universal`, then the tray helper and CLI into `Contents/Helpers` | DMG |
| Windows | `wails build -platform windows/amd64,windows/arm64 -nsis`, then `makensis` again with the CLI for each processor (`build/windows/installer/project.nsi`, Wails' script plus the CLI) | one installer for x64 and ARM64, a portable zip for each |
| Linux | `wails build -tags webkit2_41` on Ubuntu 22.04, then `nfpm` (`packaging/nfpm.yaml`) | .deb, .rpm, Arch package, tarball |
| SteamOS | `packaging/appimage.sh`: linuxdeploy with its GTK plugin, WebKitGTK's helper processes copied in, and the library pointed at them; `packaging/appimage-smoke.sh` starts it with the system's WebKitGTK moved away | AppImage |

The Windows installer cross-builds on Linux too (`wails build -platform windows/amd64 -nsis` with `nsis` installed), and the AppImage builds on any Ubuntu 22.04 or later with the Linux prerequisites, ImageMagick, and Python 3.

The app finds the homelab folder in this order: the one chosen in Setup, `$HOMELAB_ROOT`, `~/Homelab`, `~/homelab-setup`. `make frontend-check` (also in CI) checks that the scripts parse and that every element `app.js` looks up exists. To see the frontend without Wails, `make screenshots` opens it in Chromium with the fake backend in `preview/mock.js` (the real catalog, example state) and writes `docs/images/app-*.png`; `node preview/shoot.mjs status` takes one screen.

It is a separate Go module (`app/go.mod`, pointing at the repo with a `replace`), so the CLI and CI do not depend on Wails.
