# Homelab Wizard (desktop app)

A [Wails v2](https://wails.io) app over the same engine as the `homelab` CLI: Go in `app.go`, a plain HTML/JS frontend in `../web/dist` (no npm build step; the root module embeds it as package `web`, so `homelab serve` shows the same screens on a phone). What the app shares with the CLI and the menu bar item is `internal/core`.

| Screen | What it does |
|---|---|
| Choose stacks | **Start here** cards for the five starter picks, then **Add more** with every app by category and the presets (the bundles only). A search box (by name, what an app does, or what it replaces: "Spotify" finds Navidrome). Every app with what it replaces, whether it is running, and Open and Settings links. Tick apps or click a preset; dependencies are added and the plan updates live. The plan says in one line how many apps it installs and lists the ones you picked; helpers, apps already running, port moves, and settings written wait under **Details**. An app that needs a setting (the VPN key for qBittorrent) names it, and the field appears below with where to find it; values go to `.env` and are never shown back. Install streams each step. |
| Backups | Each installed app's newest database dump or volume archive (fresh, stale after 26 hours, or none yet), its size and how many are kept, when the settings file was last copied, the backup destination, and the last restore test with how long it took (or a failure since, in red; hover for the drills on record) and how to do the next one. Off-site jobs lists each Duplicati job's last run, when it runs next, its size, and its error (it signs in to Duplicati's API with `DUPLICATI_PASSWORD`). With no jobs yet, it offers **Create the backup jobs** (`homelab duplicati setup`). **Back up now** runs the nightly backup on the spot; **Test a restore** (once the Homelab AppData job has run) has Duplicati restore a dozen files and checks each against the live one; **Open Duplicati** opens Duplicati; **Recovery kit** opens the printable page. **Moving to a new machine** has **Move out…** (asks where to save the file, then backs up, stops the apps, and packs them; click twice) and **Move in…** (choose that file on the new machine), the same as `homelab move out` and `move in`. |
| Status | Tiles for running apps, what needs a look, the yearly savings (with a sparkline of the last 90 days and the change, from the nightly backup), and nightly updates. Apps by category, changing as things happen (the engine's events; checked again every minute), with only what changed redrawn, so the keyboard keeps its place: a category where every app runs folds into one line with its apps' names (click to open it; **Show every app** opens them all, and the choice is kept), while what needs a look and a category with something stopped stay open. Each row shows the app's state, one address (its address on this machine in the tooltip), how long it has been up, a *restarted N×* badge when Docker had to restart one that stopped on its own, *Not answering* (with why) when it runs but its page does not answer, *settings changed* when it still runs settings that changed since it started, and *x% up this week* when it passed fewer than 99% of the watchdog's checks in the last 7 days. Its buttons appear when the row is pointed at or focused (always on a phone): the phone button (its address as a QR code, with what the phone needs and the app's phone app), the key button on apps the homelab made a login for (Nginx Proxy Manager, AdGuard Home, Duplicati, PsiTransfer: the user name, and the password copied and cleared after 90 seconds), Restart, Update (first the release notes newer than the version it runs, then pull the newest image and recreate), the rewind button after an update, Stop or Start, and Logs (its last 200 lines, with Open Dozzle when Dozzle runs, and **Explain this log** when Ollama has a model on this machine). Baseline apps that are missing get Install. **Fix it** (`homelab fix`) appears when a baseline app is down, one is unwell or not answering, or one runs changed settings, and shows the plan first. **Watchdog** shows its last run (every 15 minutes once the jobs are installed): all checks passed, or each failing check with what it said and since when and a **Fix it** button, and a note when it has not run for 45 minutes. **Protection** (while CrowdSec and the proxy run) says whether bans are enforced, with **Fix** when they are not (it reconnects the proxy to CrowdSec), how many attacks CrowdSec caught this week and how many addresses are banned now, and the latest three with their address, country, and network, read once a minute. **Recent alerts** lists what Watchtower, Duplicati, Uptime Kuma, and the watchdog sent to ntfy in the last 12 hours, with a green dot for recoveries and red for urgent ones (it needs the read token `notify setup` makes). **What's using power** shows each busy app's share of a core with a line of its last five minutes, sampled every 10 seconds while Status is open. **Photos per person** and **What the apps keep** (the six largest folders in `data/appdata`) come from the nightly backup's `data/storage.json`. **This week** is the Sunday summary (`homelab digest`) at any time, with what needs a look marked. |
| Setup | This machine, the runtime, and the homelab folder; then the first-time setup as a checklist with a live check per step (the tailnet addresses in Home mode, or AdGuard answering, token valid, certificate served, and tunnel running with a domain; jobs installed), each saying what it gives you before how, a button for each step the CLI can do, and a Done box for the ones only a person can (a router reservation). **Do the steps I can** runs every ready step in turn and stops at the first that fails or needs you. **Make a diagnostics report** ends with **Show in Finder**, so the file is one click from being shared. Same checklist as `homelab setup`. Beside the version it says whether GitHub has new changes; when it does, a card lists them with **What is new** and **Update** (`homelab upgrade`: fast-forward only, then `up`). On a Mac, **Update** then downloads the newest app build (the latest build (Releases › Latest), or the newest `v*` release with `UPDATE_CHANNEL=stable`), checks its SHA-256 against GitHub's, replaces the running app, and opens it again (`internal/selfupdate`); when only the app is behind, the card offers **Update now**. On Windows and Linux the card opens the release builds instead. The sidebar says **● Update ready** on every screen when either has an update (checked at start and every hour). Release builds carry their commit (`-X main.commit`) for this comparison. The machine card shows the free space on each disk the homelab writes to (in red under 5%, with where to free some), starts the tray at login, and the AppImage adds itself to the app menu (with its icon) on request; when it starts from a new place and the file those entries start is gone, it points them at itself. |
| Status: moving and cleaning up | Apps running *elsewhere* (an older setup) get **Move in**, which shows `homelab adopt`'s plan and runs it on confirm. **Clean up old containers** does the same for `homelab cleanup`. |
| Add your own app | At the bottom of Choose stacks: a name, an image, a web port, and folders to keep. Runs `homelab custom add`, then ticks the new app so the plan shows what installing it does. |
| Settings | **People** first: the household (`homelab person`), each with **Welcome page**, **New sign-in link**, and **Remove** (sign-in off, data kept), and **Add a person** with their name, email, and the apps they use; without Pocket ID running it offers **Install Pocket ID**. Then **Phones**: the phones paired with the phone companion (`homelab serve`), with when each was last seen, Allow changes or Make read-only, Remove, and Pair a phone (a QR code drawn on the Go side, the one-time code, and the links, plus the same link with `&kiosk` for a TV or a wall tablet, which then shows Status alone, large, without buttons). Then `.env` as a form, grouped and explained from `.env.example`: the everyday settings first (where things are, the accounts, how it behaves, and what an installed app or a Setup step needs), with ports, versions, generated passwords, and internal addresses behind **Show all settings**; search looks through everything. Passwords and tokens are never sent to the page: their fields say whether a value is set, and empty keeps it. After saving, each setting shows whether its setup step now passes. Logins, tokens, the heartbeat URL, and the backup and media folders have a **Test** button that saves a value you just typed, then checks it with the real service (AdGuard and NPM sign-ins, the Cloudflare token reading the zone and the tunnel, the tunnel token, a heartbeat ping, writing a file in the backup folder). **Copy** beside a saved password or token puts it on the clipboard (from the Go side, so it never reaches the page) for the password manager, and clears the clipboard after 90 seconds. Folder settings (`BACKUP_DESTINATION`, `MEDIA_ROOT`, and the like) have **Choose…**, the system folder picker. |
| Connect the apps | After an install (or with Status › More… › Connect apps): Prowlarr gets Sonarr, Radarr, and Lidarr and FlareSolverr; qBittorrent becomes their download client (needs `QBITTORRENT_PASSWORD` in `.env`). Seerr and Bazarr need a sign-in, so they show as next steps. Same engine as `homelab wire`. |
| Menu bar | Apps running and healthy, what the running apps replace in subscriptions a year, the checks the watchdog alerted about (click for Status), the newest alert from the last 12 hours (click for Status), when the last backup ran (click for Backups; it warns past 26 hours), *Update ready* when the homelab has changes waiting on GitHub, or *Update ready: a new Homelab Wizard* when a newer app build is out (checked once an hour; click for Setup), quick links to running apps, Add apps, Open Homelab Wizard, Back up now, pause or resume nightly updates, Quit. Starts with the app and refreshes every minute. |

Setup's machine card turns on **Start at login** for the menu bar item (the tray icon on Windows and Linux): a LaunchAgent in `~/Library/LaunchAgents` on macOS, an entry in `~/.config/autostart` on Linux (for an AppImage, it starts the AppImage file), and a value in the user's Run key on Windows. Keyboard: Cmd (Ctrl on Windows and Linux) with 1 to 5 picks a screen in sidebar order, comma opens Settings, R refreshes the screen, F finds (Choose stacks, Settings), plus and minus make the text bigger or smaller (80% to 200%, kept on this machine) with 0 back to the usual size, and Escape clears a search. Every link that acts (Open Setup, Show, go back) is reached with Tab and pressed with Enter or Space. For VoiceOver, picking a screen moves to its heading and marks the sidebar button as the current page, logs are announced as logs, and errors and results are read out when they appear. On the Mac the window follows the platform: the window buttons sit in a translucent sidebar (as in Finder and Mail), and the menu bar has the app, Edit, View (the screens, Settings… ⌘, and Reload ⌘R), Window, and Help menus, with an About panel showing the version. On Windows 11 the navigation pane sits on Mica (build 22621 and later; older Windows keeps an opaque window) with Segoe UI Variable, a grey selection and the accent pill beside it as in Settings, accent badges, 4px controls, and thin scroll bars; on Linux the sidebar and controls follow the neutral look GNOME and KDE share. Each platform uses its own greys and accent colour rather than the logo's navy. Everywhere, buttons show the arrow rather than a hand, labels do not select (fields, logs, and errors do), and focus rings appear for the keyboard only. The menu bar item runs as its own process. On macOS it is a helper inside the bundle (`Contents/Helpers/homelab-tray`, built from `cmd/homelab-tray`), because Wails and the tray library cannot share one binary there; on Windows and Linux the app binary runs it with `--tray`. On Linux it needs a desktop with a status-notifier tray (KDE, or GNOME with the AppIndicator extension).

## Run and build

Needs Go 1.25+ and the Wails CLI: `go install github.com/wailsapp/wails/v2/cmd/wails@v2.16.0`, then `wails doctor` for the platform prerequisites (Xcode command line tools on macOS; `libgtk-3-dev` and `libwebkit2gtk-4.1-dev` on Linux, built with `-tags webkit2_41`; WebView2 on Windows, already present on Windows 11).

```bash
cd app
wails dev                 # live window; edits to ../web/dist reload (wails.json assetdir)
wails build               # build/bin/Homelab Wizard.app (macOS), homelab-wizard(.exe)
```

The packages are built by `.github/workflows/release.yml` ([Releasing](../docs/Releasing.md#each-platforms-build) lists what each holds):

| Platform | How | Files |
|---|---|---|
| macOS | `wails build -platform darwin/universal`, then the tray helper and CLI into `Contents/Helpers` | DMG |
| Windows | `wails build -platform windows/amd64,windows/arm64 -nsis`, then `makensis` again with the CLI for each processor (`build/windows/installer/project.nsi`, Wails' script plus the CLI) | one installer for x64 and ARM64, a portable zip for each |
| Linux | `wails build -tags webkit2_41` on Ubuntu 22.04, then `nfpm` (`packaging/nfpm.yaml`) | .deb, .rpm, Arch package, tarball |
| SteamOS | `packaging/appimage.sh`: linuxdeploy with its GTK plugin, WebKitGTK's helper processes copied in, and the library pointed at them; `packaging/appimage-smoke.sh` starts it with the system's WebKitGTK moved away | AppImage |

The Windows installer cross-builds on Linux too (`wails build -platform windows/amd64 -nsis` with `nsis` installed), and the AppImage builds on any Ubuntu 22.04 or later with the Linux prerequisites, ImageMagick, and Python 3.

The app finds the homelab folder in this order: the one chosen in Setup, `$HOMELAB_ROOT`, `~/Homelab`, `~/homelab-setup`. `make frontend-check` (also in CI) checks that the scripts parse and that every element `app.js` looks up exists. To see the frontend without Wails, `make screenshots` opens it in Chromium with the fake backend in `preview/mock.js` (the real catalog, example state) and writes `docs/images/app-*.png`; `node preview/shoot.mjs status` takes one screen.

It is a separate Go module (`app/go.mod`, pointing at the repo with a `replace`), so the CLI and CI do not depend on Wails.
